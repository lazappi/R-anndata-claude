# zarr fixtures and encoding table

Status: ready-for-agent
Type: task
Blocked by: none

## What

Generate the zarr fixture set and the zarr encoding table (spec "Encodings" and "Fixtures").

- Python writes each fixture case as a v3 store (Python defaults: sharded and consolidated) and a v2 store into `tests/testthat/fixtures/zarr/`, plus unsharded, unconsolidated and per-compressor (zstd, blosc, gzip, none) v3 variants
- A generated zarr encoding table (alongside `.scratch/h5ad-io/encoding-table.md`) records, for every case and both versions, the dtype, codecs, fill value, attributes and layout Python writes, with a freshness test like the h5ad one
- Extend `h5_tree.py`/`expect_structurally_equivalent()` (or add zarr counterparts) so Structural equivalence can be checked between two zarr stores and between a zarr store and an h5ad file, ignoring chunk shape, codecs and shard layout
- Keep fixture size small (the h5ad set is the model)

## Acceptance criteria

- Fixtures and the encoding table are committed and regenerated by `scripts/regenerate-fixtures.sh`
- Structural equivalence helpers work for zarr stores, with tests on Python-written pairs (equal and deliberately different)
- `scripts/check.sh` passes
